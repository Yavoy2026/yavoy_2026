# Логотипы платёжных систем

Требование п.5 «Выполнение требований Банка к сайту» (АО «Октобанк», YAV-21):
на сайте должны быть размещены марки платёжных систем, которые принимаются к оплате.

Компонент `src/components/PaymentSystems.tsx` берёт файлы отсюда по именам из
списка `SYSTEMS`. Расширение задано явно: Humo официально отдаёт марку растром.

| Файл             | Откуда взят                                                        |
|------------------|--------------------------------------------------------------------|
| `visa.svg`       | Wikimedia Commons, `Visa Inc. logo (2021–present).svg`             |
| `mastercard.svg` | Wikimedia Commons, `Mastercard-logo.svg`                            |
| `unionpay.svg`   | Wikimedia Commons, `UnionPay_logo.svg`                              |
| `uzcard.svg`     | logo-teka.com (вертикальный лендинг-лок, фирменные #001A70/#FF6720) |
| `humo.png`       | **официальный** humocard.uz → «Правила размещения логотипа»          |

`humo.png` уменьшен до 240 px по ширине: оригинал с сайта Humo весит 900 кБ,
для футера это неприемлемо.

## Что стоит сделать перед боем

Марки взяты из открытых источников, и визуально они верные, но **банк сверяет
размещение с brand guidelines платёжных систем**. Надёжнее запросить пакет марок
у самого Октобанка: эквайеры выдают мерчанту готовый набор под свои требования —
это те же файлы, которые банк потом и будет проверять. Тогда достаточно заменить
файлы здесь, код трогать не нужно.

Отдельно у Humo есть `GuidebookHUMO.pdf` с правилами размещения — если банк
придерётся, ответы там.

## Правила

- **Нельзя** рисовать марки самостоятельно: банк сверяет с brand guidelines.
- Список принимаемых систем должен совпадать с тем, что реально подключено
  в договоре эквайринга: показывать марку системы, которой платить нельзя, —
  нарушение.
- Пока файла нет, вместо марки выводится текстовая подпись: страница не ломается,
  но требование банка формально не закрыто.
